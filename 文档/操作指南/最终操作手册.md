# DONGJIN 最终操作手册

## 1. 操作原则

所有会改变数据、模型或运行状态的操作都由用户显式执行。系统不会因为造数完成而
自动训练，不会因为训练完成而自动选择模型，也不会因为页面刷新而自动研判。

以下命令均从项目根目录 `E:\Java\DONGJIN` 执行：

```powershell
cd E:\Java\DONGJIN
$python = ".\python-training-service\.venv\Scripts\python.exe"
```

## 2. 启动基础服务

### 2.1 Neo4j

```powershell
neo4j console
```

保持窗口运行。项目使用已有Neo4j，不会自动安装或开机启动。

### 2.2 Memurai

```powershell
.\scripts\start-memurai.ps1
.\scripts\status-memurai.ps1
```

服务启动类型保持 `Manual`，最大内存为256 MB。停止：

```powershell
.\scripts\stop-memurai.ps1
```

### 2.3 Python计算服务

```powershell
cd E:\Java\DONGJIN\python-training-service
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

### 2.4 Java和前端

Java可从IDEA启动 `DongjinApplication`。前端：

```powershell
cd E:\Java\DONGJIN\frontend
npm run dev
```

## 3. 数据与训练分支

### 3.1 只生成场景和白箱数据集

```powershell
& $python .\scripts\generate_training_dataset.py --samples-per-type 8 --random-seed 20260724
```

输出包含 `batchId`、`datasetId`、CSV/Parquet路径和预览路径。完成后不会训练。
该命令在当前PowerShell前台运行，当前输出就是进度状态；需要停止时按 `Ctrl+C`。
临时目录会由服务清理，不会发布半成品数据集。

### 3.2 只训练指定数据集

```powershell
& $python .\scripts\train_offline_model.py --dataset-id <datasetId> --maximum-epochs 120
```

完成后只保存模型和指标，不会设为在线模型。
训练同样在当前PowerShell前台运行，可用 `Ctrl+C` 停止；未原子发布的临时模型目录
会被清理。

### 3.3 独立评估

```powershell
& $python .\scripts\evaluate_offline_model.py --model-id <modelId> --dataset-id <datasetId> --split test
```

结果位于 `python-training-service\artifacts\model-evaluations`，不改变模型选择。

## 4. 人工模型管理

```powershell
& $python .\scripts\list_inference_models.py
& $python .\scripts\check_inference_model.py --model-id p1-v1-gcn-model-v3
& $python .\scripts\select_inference_model.py --model-id p1-v1-gcn-model-v3
```

人工回滚：

```powershell
& $python .\scripts\rollback_inference_model.py
```

当前选择写入 `config\inference-model.json`，历史位于
`python-training-service\artifacts\model-selection-history`。

## 5. 在线运行与研判

先在网页生成/发布P1，再启动连续潮流。拓扑页每秒读取一次Redis当前完整快照。

单次正式研判：

```powershell
& $python .\scripts\diagnose.py current
```

显式启动、查看和停止周期研判：

```powershell
& $python .\scripts\diagnosis_monitor.py start
& $python .\scripts\diagnosis_monitor.py status
& $python .\scripts\diagnosis_monitor.py stop
```

周期研判由正在运行的Python服务持有；关闭服务后自动停止。

## 6. 影子错误盲测

```powershell
& $python .\scripts\shadow_fault.py create --event-type LINE_OUTAGE
& $python .\scripts\diagnose.py shadow --session-id <sessionId>
& $python .\scripts\diagnose.py reveal --session-id <sessionId>
& $python .\scripts\shadow_fault.py close --session-id <sessionId>
```

创建结果不返回真实类型和位置；必须完成盲判后再执行 `reveal`。

## 7. 独立短路分析

SimBench P1没有外部电网短路容量和R/X，必须提供来自已知数据源的参数：

```powershell
& $python .\scripts\short_circuit.py run `
  --target-id simbench-1-mv-urban-0-sw:bus:0 `
  --fault-type 3ph `
  --s-sc-mva 1000 `
  --rx 0.1
```

上面的 `1000/0.1` 仅演示命令格式，不能当作真实工程参数。单相接地短路还需要P1
目前没有的零序参数，因此系统会明确拒绝，不会自动补假值。

## 8. 产物位置

| 内容 | 目录 |
|---|---|
| P1权威电网包 | `python-training-service\artifacts\grids` |
| 离线场景 | `python-training-service\artifacts\scenarios` |
| GNN数据集/CSV | `python-training-service\artifacts\datasets` |
| 模型 | `python-training-service\artifacts\models` |
| 独立评估 | `python-training-service\artifacts\model-evaluations` |
| 在线研判白箱档案 | `python-training-service\artifacts\diagnoses` |
| 影子会话 | `python-training-service\artifacts\shadow-sessions` |
| 短路分析 | `python-training-service\artifacts\short-circuit` |

所有新产物都在E盘项目目录中，可直接打开。

研判档案默认不会在页面刷新时生成；只有单次/周期研判会落盘。人工预览30天以前的
档案：

```powershell
& $python .\scripts\cleanup_diagnosis_archives.py --older-than-days 30
```

确认列表后才执行删除：

```powershell
& $python .\scripts\cleanup_diagnosis_archives.py --older-than-days 30 --apply
```
