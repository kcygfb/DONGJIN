# DONGJIN 数据白箱字典

## 1. 数据层级

| 层级 | Schema | 作用 |
|---|---|---|
| P1 | `grid-schema-v1` | 静态设备、额定参数、稳定businessId和拓扑关系 |
| 动态快照 | `grid-snapshot-v1` | 同一simulationTime的完整潮流画面 |
| 量测帧 | `grid-measurement-v1` | Truth经过噪声、缺失等量测转换后的输入 |
| 特征帧 | `grid-feature-frame-v2` | 按稳定businessId排序的48维模型输入 |
| 研判 | `grid-diagnosis-result-v1` | 模型、规则、拓扑和解释结果 |
| 短路 | `grid-short-circuit-result-v1` | 与连续潮流隔离的短路计算结果 |

## 2. 当前快照

“快照”是一个时刻的完整数据画面。前端每秒读取Redis活动指针，展示该
`snapshotId`下所有节点和线路的数据，不会把不同帧拼接。

- 母线：`vmPu`、`vaDegree`、`pMw`、`qMvar`
- 线路：两端有功/无功、两端电流、负载率、损耗
- 变压器：高低压侧功率/电流、负载率、损耗、分接头
- 开关：闭合状态、在运状态
- 负荷/电源：有功、无功

Redis只保存当前活动指针和带TTL的短期数据，不因网页每秒读取而无限增长。

## 3. 48维特征

| 序号 | 特征 | 影响 |
|---:|---|---|
| 1–8 | `type.bus/line/trafo/switch/load/sgen/gen/ext_grid` | 区分设备类型 |
| 9 | `topologyDegree` | 表示拓扑邻接规模 |
| 10 | `ratedVoltageKv` | 额定电压 |
| 11 | `ratedPowerMva` | 额定容量 |
| 12 | `lengthKm` | 线路长度 |
| 13–15 | `vmPu`、`.missing`、`.deltaFromBaseline` | 电压、缺失和基线偏差 |
| 16–18 | `vaDegree`、`.missing`、`.deltaFromBaseline` | 相角、缺失和基线偏差 |
| 19–21 | `pMw`、`.missing`、`.deltaFromBaseline` | 有功、缺失和基线偏差 |
| 22–24 | `qMvar`、`.missing`、`.deltaFromBaseline` | 无功、缺失和基线偏差 |
| 25–27 | `currentKa`、`.missing`、`.deltaFromBaseline` | 最大端电流及偏差 |
| 28–30 | `loadingPercent`、`.missing`、`.deltaFromBaseline` | 热负载率及偏差 |
| 31–33 | `lossMw`、`.missing`、`.deltaFromBaseline` | 有功损耗及偏差 |
| 34–36 | `inService`、`.missing`、`.deltaFromBaseline` | 在运状态及变化 |
| 37–39 | `closed`、`.missing`、`.deltaFromBaseline` | 开关闭合状态及变化 |
| 40–42 | `scaling`、`.missing`、`.deltaFromBaseline` | 负荷/电源缩放及变化 |
| 43 | `missingFieldCount` | 单设备缺失字段总数 |
| 44–48 | `quality.GOOD/SUSPECT/BAD/MISSING/FROZEN` | 数据质量独热编码 |

缺失值本身填0，但对应 `.missing=1`，所以真实0和缺失0可以区分。在线归一化只使用
所选模型目录内冻结的 `normalization.json`。

## 4. 白箱文件

每次研判目录至少包含：

- `input-measurement.json`
- `feature-frame.json`
- `feature-frame.csv`
- `probabilities.csv`
- `result.json`
- `README.md`

模型真值、原始预测、规则事实和最终结论分层保存。
